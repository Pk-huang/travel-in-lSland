### 整合測試 (Integration Test) ---> 層級: 2 *系統面整合測試

如何組成功能

3D 地形視覺化，讓使用者可以瀏覽冰島地貌：

流程：
data source → validate / normalize → transform function → mesh / geometry → scene setup → renderer → canvas → GPU → rendering

流程（中文）：
data source → 資料驗證 / 正規化 → 轉換 function → mesh / geometry → scene setup → renderer → canvas → GPU → 渲染

流程分割測試

### Data

對應流程 data source → validate / normalize → transform function

1. Source / API / JSON

   工作：提供原始資料，讓 3D canvas 可以產生繪製地圖。

   內容：取得地形資料、地貌資料，並確保可由 API / JSON 載入到後續流程。

   功能與測試內容：

   - API 是否能夠順利連線並下載，且具備備用資料來源

     功能目的：確認資料來源穩定且具備失敗時的回復機制。

     測試內容：驗證主資料源可用性，確認失敗時是否可切換至備用資料來源。

     驗證條件：主資料源成功時使用主資料源，主資料源失敗時自動 fallback 至備用資料來源，系統不崩潰。

   - API 內容是否已轉換成 render 所需的 data

     功能目的：確認原始資料已轉換成後續流程可直接使用的資料結構。

     測試內容：檢查原始 API / JSON 是否已成為 render-ready 資料，符合 map / canvas 流程契約。

     驗證條件：資料可直接進入後續轉換與渲染流程，不需要手動修正格式。

   - 設定優先順序與載入順序

     功能目的：確認多個資料來源時，系統按正確優先順序選用並依序載入。

     測試內容：檢查資料載入順序與優先層級是否符合設定。

     驗證條件：地形資料先載入，地貌資料依必要順序後載入，且順序穩定。

2. Validation / schema / fallback

   工作：驗證資料是否完整、格式正確，並在失敗時提供回復機制。

   內容：檢查資料契約、資料完整性、缺失欄位處理與 fallback 策略。

   功能與測試內容：

- 資料來源與資料完整性驗證

    功能目的：確認 API / JSON 提供的資料可被後續地圖流程正確解析與使用。

    測試內容：檢查 API 是否可提供可用資料、資料格式是否完整、是否含有必要欄位、是否可進入後續流程。

    驗證條件：回應成功、資料內容完整、格式正確、必要欄位存在、可被後續流程使用。

    測試覆蓋現況：
  - 已覆蓋：API 200 + JSON parse、主來源成功時採用主資料。
  - 缺口與補測規劃：外部來源穩定性證據不足（受測試環境 timeout 影響）。
  - 結果：部分已驗證。
  - 成功率：NOAA 20/20（100%）；APIs.is 0/20（0%）。

- JSON 資料格式是否完整

    功能目的：確認 JSON 可被解析並符合地圖渲染所需的資料契約。

    測試內容：檢查欄位是否完整、資料型別是否正確、是否存在空值或破損資料。

    驗證條件：JSON 可解析、必要欄位存在、資料型別正確、無缺失或損壞資料。

    測試覆蓋現況：
  - 已覆蓋：必要欄位驗證、欄位型別驗證、schema parse 成功/失敗路徑。

- 地理資料與數值範圍驗證

    功能目的：確認地形與地貌資料具備有效的地理資訊與數值範圍。

    測試內容：檢查座標、範圍、高度、標記資料是否存在且合理。

    驗證條件：地理範圍、座標、高度、標記資料完整且有效。

    測試覆蓋現況：
  - 已覆蓋：結構可用性與座標 fallback 行為（可進入 render pipeline）。
  - 缺口與補測規劃：合理範圍規則尚未明確驗證。
  - 結果：部分已驗證。
  - 成功率：既有相關測試 36/36 通過。
  - 待補：經緯度上下限、高度區間、極端值邊界（NaN/Infinity/超大值）。

- 異常資料處理

    功能目的：確認系統在資料錯誤時能安全處理，不會直接崩潰。

    測試內容：檢查缺失欄位、空值、錯誤格式、解析失敗時的處理方式。

    驗證條件：系統能記錄錯誤、切換備用資料或回傳明確錯誤訊息。

    測試覆蓋現況：
  - 已覆蓋：timeout / 403 / 500 / 空回應錯誤轉換、主失敗切 fallback、備援失敗切 local snapshot、空資料不崩潰。

### Data transformation layer

對應流程 transform function → mesh / geometry → scene setup → renderer → canvas →

本階段補測範圍（僅保留第 2、3 項）：
- 錯誤分類與可觀測性
- CRS/座標軸錯置檢查

1. Transform / data conversion

   工作：將原始資料整理成可供地圖渲染的資料契約，並在異常時提供安全的 fallback。

   內容：schema / data contract、欄位驗證、資料正規化、轉換 function、錯誤處理與備用資料策略。

   功能與測試內容：

   - Data contract / schema 定義

     功能目的：確認資料轉換前後都遵守明確的契約，避免後續渲染流程因欄位或型別不一致而崩潰。

     測試內容：驗證 schema 是否定義必要欄位、型別、範圍與命名規則，並確認轉換後資料仍符合 render contract。

     驗證條件：schema 規範涵蓋所有必要欄位，轉換後資料型別正確、必要值存在，且可被後續流程直接使用。

   - 必要欄位與型別驗證

     功能目的：確認資料在進入渲染前已具備完整且可解析的結構。

     測試內容：檢查缺失欄位、空值、錯誤型別、異常格式是否會被標記並處理。

     驗證條件：資料若完整則正常流轉；若缺欄位或型別錯誤，系統將回報明確錯誤並採取 fallback。

   - 地理座標與數值範圍驗證

     功能目的：確認地形與地貌資料具備有效地理資訊與合理數值範圍，避免渲染結果失真或崩潰。

     測試內容：檢查座標是否合理、範圍是否落在冰島邊界內、高度是否在可接受區間、標記資料是否完整。

     驗證條件：所有有效資料都符合地理範圍與數值邊界；異常值會被拒絕、修正或切換 fallback。

   - 原始資料轉成 render-ready data

     功能目的：確認原始 API / JSON 能被轉換為後續 mesh / geometry / scene 流程可直接使用的結構。

     測試內容：檢查資料轉換是否正確產出 render-ready payload，包含座標、高度、顏色、解析度資訊等必要欄位。

     驗證條件：轉換結果可直接進入渲染流程，不需手動補修資料格式或欄位。

   - Error handling / fallback

     功能目的：確認資料異常時系統可安全回復，不因資料錯誤而中斷地圖載入。

     測試內容：驗證解析失敗、欄位缺失、型別錯誤、來源不可用時是否會切換至備用資料或回傳明確錯誤訊息。

     驗證條件：系統不崩潰，且可依設定選擇 fallback、錯誤記錄或降級渲染。

   - 地形高度、顏色與解析度差異轉換

     功能目的：確認不同資料來源與解析度下的高度、顏色與細節資訊能保持一致且可渲染。

     測試內容：檢查不同 DEM / 樣本解析度、地貌資料與顏色映射是否正確，且轉換後保持可視與一致性。

     驗證條件：高度與顏色映射結果符合預期，解析度差異不會導致資料錯位或渲染失真。

   - API / JSON / source priority 與載入順序

     功能目的：確認資料來源有明確優先順序，且載入順序符合流程依賴。

     測試內容：驗證主資料源、備用資料源、JSON 優先順序是否正確，且資料載入前後順序符合 pipeline 設計。

     驗證條件：依設定優先使用正確來源，且在 render pipeline 啟動前完成必要資料載入與轉換。

2. Render preparation / compatibility

   工作：將已轉換完成的資料整理成渲染器與互動系統可直接使用的準備層。

   內容：渲染相關設定、解析度切換、畫布與相機參數、quality mode、interaction spec、光影與場景相容性。

   功能與測試內容：

   - 渲染座標與地形顏色設定

     功能目的：確認轉換後資料在渲染前已正確對應到三維空間座標與視覺顏色。

     測試內容：驗證座標系統、地形高度映射、顏色資料與 mesh geometry 是否對齊。

     驗證條件：地圖在三維空間中的位置與色彩符合設計，且不出現偏移、反轉或顏色錯配。

   - Resolution / quality modes

     功能目的：確認不同解析度與品質模式可正常切換，並保有可接受的渲染效果與效能。

     測試內容：驗證 low / medium / high 或等價品質模式是否正確改變解析度與顯示細節。

     驗證條件：模式切換後產生對應的渲染結果，且不破壞整體場景穩定性。

   - Camera / interaction spec

     功能目的：確認相機設定與互動規格符合使用者操作需求與場景配置。

     測試內容：驗證相機初始姿態、縮放範圍、旋轉限制、拖曳與視角切換設定是否符合設計。

     驗證條件：使用者可以正常操作相機，且視角、限制與交互行為穩定、可預測。

   - 畫布大小、viewport、DPR 設定

     功能目的：確認渲染區域與解析度設定適合不同螢幕與裝置，避免變形或低清晰度。

     測試內容：檢查 viewport、canvas 尺寸、DPR、響應式重算是否正確執行。

     驗證條件：畫布在不同大小與裝置下均保持正確比例、清晰度與可視範圍。

   - 解析度切換

     功能目的：確認在不同解析度下，地圖仍可穩定重新計算與重新渲染。

     測試內容：驗證解析度變更時是否重新配置 geometry、texture、camera、renderer 設定。

     驗證條件：切換解析度後畫面不失真、不崩潰，且維持可交互狀態。

   - 光影、時間與場景參數

     功能目的：確認光源、陰影與時間參數能正確影響地圖視覺效果，且在場景中保持一致。

     測試內容：檢查 light、shadow、time of day / environment 設定是否正確套用到場景。

     驗證條件：各參數變更後與預期一致，且不破壞地形顯示或互動性能。

   - 渲染器相容性與效能準備

     功能目的：確認 render pipeline 與環境設定能符合 browser / GPU / device 相容性要求。

     測試內容：驗證 renderer 設定、device pixel ratio、fallback、性能優化與場景初始化是否建構正確。

     驗證條件：系統能在目標環境中正常初始化渲染，並維持穩定的效能與可用性。

### map : canvas

工作：根據資料與 render settings 產生最終地圖結果。

內容：只負責顯示最終渲染結果，不處理資料判斷、fallback 或資料轉換邏輯。

功能與測試內容：

- Canvas / WebGL / GPU 渲染

  功能目的：確認最終畫布能正確初始化、渲染並持續更新地圖內容。

  測試內容：驗證 WebGL / canvas 初始化、renderer pipeline、frame 更新與顯示是否正常。

  驗證條件：地圖成功顯示在畫布上，且不出現黑屏、空白或渲染中斷。

- 3D 地形 mesh 與 geometry

  功能目的：確認 terrain mesh 正確生成，且與輸入資料對應。

  測試內容：檢查 geometry、vertex、face、mesh 連接是否正確，地形輪廓與高度是否符合資料。

  驗證條件：地形能正確呈現高低起伏，且不出現破裂、扭曲或漏繪。

- Scene setup 與 renderer pipeline

  功能目的：確認場景、相機、渲染器與物件層級配置正確，形成可視的 3D 地圖。

  測試內容：驗證 scene setup 是否包含正確的 camera、mesh、lighting、group / layer 組織方式。

  驗證條件：3D 場景可完整呈現，且所有必要物件都位於正確位置與層級。

- Camera / interaction / controls

  功能目的：確認使用者可以正常觀看與操作 3D 地圖，且互動行為符合設計。

  測試內容：檢查旋轉、縮放、拖曳、視角切換、相機飛行是否正常工作。

  驗證條件：使用者操作後視角回應正確、無卡頓、無錯亂、且範圍限制符合規格。

- Light / shadow / time of day

  功能目的：確認光照與陰影設定能提升地圖視覺效果，同時維持可讀性與穩定性。

  測試內容：驗證 light、shadow、time of day / environment 參數是否正確影響地形顯示。

  驗證條件：光影效果符合預期，且不造成可視性問題、過曝、過暗或錯誤陰影。

- Performance / FPS / memory usage

  功能目的：確認地圖在實際使用環境中能維持穩定渲染效能，不造成明顯卡頓。

  測試內容：檢查 FPS、畫面更新穩定性、記憶體使用量、渲染負擔與拖曳/縮放時的流暢度。

  驗證條件：在目標環境中可維持穩定渲染，且 FPS 不低於預定目標，必要時能進行降級處理。
